# research/

Background and design documents, newest design first. They record the reasoning behind the code and are
not read by it.

| Document | What it is |
| --- | --- |
| `dataset-survey.md` | The dataset survey: every candidate dataset by category, licence, labelling method, balance and overlap, what was decided, how to fill the gaps, and when synthetic data is safe for evaluation |
| `mvp-plan.md` | The MVP: what it must prove, the slice, gates, the experiment and criteria, models, sizing |
| `implementation-plan.md` | How the framework maps onto the codebase (written before the MVP was built) |
| `mvp-flow.svg` | One diagram of the MVP as built: data, splits, PROACT, generation, build, delivery and evaluation, plus what is not built yet |
| `data-framework.md` + `data-framework.svg` | The whole framework on one page: licences, splits, PROACT, generation, evaluation tiers; the diagram marks each part implemented, partial or not built |
| `generation-integration.md` | How generation fits with the real datasets and the taxonomy |
| `auragen-adjacent-survey.md` | Generation approaches adjacent to AuraGen and their usefulness here |
| `synthetic-data-review.md` | Literature and industry review of synthetic data for agent security |
| `industry-attack-data-sources.md` | Where industry gets attack data |
